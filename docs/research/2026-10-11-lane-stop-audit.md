## Why the H33 claim might be relatively strong — what can and cannot be concluded

The official metric credits a predicted pixel's **maximum** 300 m kernel match to each target, but penalizes the **sum** of unmatched prediction mass. Spacing dots at roughly kernel radius and avoiding known fault pixels can save false-positive mass compared with dense ribbons while preserving tolerant coverage. Existing H33 evidence describes a base/thinning/flank-pruning sequence with 37,654 dots. This is a **mechanistic explanation**, not a proven cause for a particular live score: no organizer receipt links H33-2-B2's exact bytes to 0.2778, the hidden truth and per-raster TP/FP are unavailable, and spatially blocked local catalogue hide-and-recover ranks the group's live artifacts poorly (`evidence/e61_instrument_audit.json`, n=12; a retrospective association, not an independent causal test). The 0.3195 user-supplied threshold is **not** the top score in the dated repository snapshot (0.4133); neither figure is a model target forecast. We cannot assert that this channel-profile lane beats 0.2778, let alone the public leader.

## Site use, blockers, and next action

[Executive summary](../executive-summary.html): download an existing research-only TIFF, inspect its format receipt and **do not submit**. For a genuinely new, separately authorized hypothesis, acquire and pin the USGS source rasters; preregister a segment-buffered hide-and-recover design; test each predictor alone (AUC >.90 is leakage until resolved); run orientation-matched random-line first test; use shared feature cache, `src/gems57/evaluate_holdout.py` and `src/gems57/submission_writer.py`; pre- and post-placement compare **all** accessible registry rasters under the literal >.90 rank / >.70 proximity thresholds; finally run byte-level local validation. A selector, not this lane, decides whether to spend a weekly slot. Competition data tab and submissions require organizer authentication, unavailable in this environment; local data includes the template and labels but **not** `training_features.tif`. The browser feed in `docs/feed.json` is a dated repository snapshot, not an automatic live portal feed. Set up a permitted authenticated integration separately if the user wants live receipts; never imply an unauthenticated scrape is current.
