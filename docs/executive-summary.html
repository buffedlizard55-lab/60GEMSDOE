Reading. The physically correct statistic is null and tightly bounded: the ksn ratio step at a withheld fault is at most ~2%. The median component is negative (-0.0449) and only 40.4% of components are positive, so the small positive mean is a tail effect. On the off-catalogue population the board actually scores, the same statistic is significantly negative. And a statistic containing no step information whatsoever — the steepness level — scores +0.1946, which is why the absolute Δksn arm and every previous "PROCEED" in this lane (H67-1 +0.4251, H68-1 +0.4502) passed: faults sit on range fronts, where channels are steep. Those results measured relief, not tectonics.

Exactly how to make a submission into the contest

  1. Decide whether the file is cleared. Read the OK/NOT-OK table at the top of this page. It is generated from registry/current_site_status.json and the run card — not from a hunch. Today: not cleared.
  2. Download the file from this page (or the .zip, which contains exactly one GeoTIFF). Both containers are single-band float32.
  3. Verify it locally before you spend a slot. The checklist the portal enforces: one band, float32, EPSG:32611, 3730×3292 at 100 m, transform (100, 0, 243350, 0, -100, 4508550), every value finite and in [0, 1], data outside the bounds null or NaN. The receipt checks-gems60-h73-chi-knick-corridor-8811px-20261011T201814Z-35930766-zeros.tif.json records all of these with the SHA-256.
  4. Why your earlier upload returned “Predicted values must be in range [0, 1]”. That is a range/NaN rejection. The file on this page is the all-finite “zeros” container: every one of the 12,279,160 cells stores a finite number in [0,1] and nothing is NaN anywhere, so a reader that ignores nodata cannot see an out-of-range value. The “nan” variant is published alongside it as a diagnostic only.
  5. Submit. On the DrivenData submissions page, sign in, choose New submission, choose File to submit, pick the .tif (or the one-TIFF .zip), and put a unique name plus a short note in the Note (optional) field — e.g. the submission name and note in the table above.
  6. Keep the receipt together with the hash. Save the organizer's score, the submission timestamp and the file's SHA-256 in one place; a score without a byte hash proves nothing about which file earned it.

Weekly cap. Promotion to a real slot is a separate selector step, inside the weekly cap shown on the submission page. This session spent 0 slots.
