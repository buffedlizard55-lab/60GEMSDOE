Irregularities flagged for review

  1. Brief staleness: “0.3195 is the highest score” — the live leaderboard top is 0.3774 (xiaofanhu), verified on the official page 2026-10-11; 0.3195 (DARD) is #8.
  2. Rules-PDF host: the brief's docs.nlr.gov/docs/fy26osti/96647.pdf did not resolve from this sandbox; the document is real and lives at www.nlr.gov/docs/fy26osti/96647.pdf (DOI 10.2172/3818146).
  3. Official sample pattern: the provided sample_submission.tif contains 60,988 ones — exactly the mapped-catalogue pixel set — while the problem page calls it “a sample submission that predicts total fault absence”. Anyone submitting the sample as-is would score ≈ the catalogue baseline, not absence.
  4. DEMO egress: this sandbox cannot reach prd-tnm.s3.amazonaws.com (3DEP tiles) or ScienceBase; the 10 m/1 m raw DEM therefore could not be pulled here. Source is named, free, official, public-domain; 716 tile URLs + sha256 pins already extracted (data/dem_links.json upstream; 706/716 tiles processed successfully in session 7GEMSDOE).
  5. Portal error root cause (historical): “Predicted values must be in range [0, 1]” is what a reader that ignores the nodata tag reports for the NaN-outside container. All our exports use the all-finite zeros container, which cannot trigger it.
  6. GitHub API rate limit (60 req/h unauthenticated) aborted bulk raster fetches mid-session; worked around with full clones.
